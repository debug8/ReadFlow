# ReadFlow — правила проєкту

Інструмент для вчителів початкових класів: підрахунок слів у тексті й перевірка швидкості читання учнів. Дві платформи, один продукт.

| Папка | Платформа | Стек |
|-------|-----------|------|
| `desktop/` | Windows 7 → 11 | C#, WPF, .NET Framework 4.8 |
| `android/` | Android 8.0+ (API 26) | Kotlin, Jetpack Compose, Material 3 |
| `docs/` | — | специфікації та плани робіт |
| `shared/` | — | спільні дані обох додатків |

**Перед роботою прочитай** відповідну специфікацію: `docs/SPEC.md` (десктоп) або `docs/SPEC_ANDROID.md` (Android). Плани робіт — `docs/TASKS.md` і `docs/TASKS_ANDROID.md`.

---

## Непорушні правила

Це рішення вже прийняті й обговорені. Не змінюй їх на свій розсуд — якщо бачиш проблему, спитай.

**1. Обидва додатки дають однакові числа.**
Це інструмент вимірювання. Якщо десктоп покаже 84 слова, а телефон 86 — довіри не буде. Правила підрахунку описані один раз у `docs/SPEC.md`, розділ 4, і однаково реалізовані в `TextStatsCalculator` обох проєктів. Змінюєш правило — правиш специфікацію, обидві реалізації **і** тести, в одному коміті.

Ключові нюанси: апостроф і дефіс не розривають слово (`комп'ютер`, `синьо-жовтий` = 1 слово), але тире й мінус — розривають; буква — це Unicode-літера **або цифра** (`2024` = слово з 4 букв), розділові знаки й пробіли не рахуються; переноси рядків нормалізуються (`\r\n` = 1 знак); округлення середньої довжини слова — «від нуля», не банківське.

Режим підрахунку абзаців — налаштування вчителя (кожен непорожній рядок / блок між порожніми рядками), а не константа. Обидві платформи мають однаковий набір режимів і однакове значення за замовчуванням.

**2. Норми WPM і тексти-зразки не хардкодяться.**
Читаються з `shared/norms.json` і `shared/samples/`. Це єдине джерело правди для обох платформ.

**3. Тільки `DynamicResource` для кольорів (WPF).**
Жодного `Background="White"`, `Foreground="#333"` чи `StaticResource` для кольорів у розмітці. `StaticResource` не оновлюється при заміні словника — тема не перемкнеться наживо. Кожна тема в `Themes/` визначає **повний** набір ключів зі специфікації; відсутній ключ = падіння при перемиканні.

**4. Весь C#-код — в одному проєкті `ReadFlow.csproj`.**
Ніяких окремих бібліотек класів. Розділення папками: `Core/`, `Models/`, `ViewModels/`, `Views/`, `Data/`, `Themes/`, `Resources/`. Єдиний виняток — `ReadFlow.Tests.csproj`.

**5. CSV — UTF-8 з BOM, роздільник `;`.**
Без BOM Excel в українській локалі покаже «кракозябри», без `;` запхає рядок в одну комірку. Екранування за RFC 4180 — окремим хелпером із тестами, не конкатенацією рядків.

**6. Мінімалізм — це вимога, а не побажання.**
Додаток для вчителя, який відкрив його вперше й не читав інструкції. Не додавай функцій, яких немає в специфікації. Розширений режим (облік учнів) за замовчуванням вимкнений і не має лишати по собі ані порожніх місць, ані сірих кнопок у базовому інтерфейсі.

**7. Розширений режим реалізується останнім.**
Задачі 13–15, тільки після повністю готових 1–12. Це окремий шар: якщо його не робити взагалі, додаток лишається повноцінним.

## Як працювати

- **По одній задачі за раз** із `TASKS.md`. Після кожної — зупинка й перевірка за критерієм «Готово, коли». Не біжи вперед.
- Мова інтерфейсу — **українська**. Назва `ReadFlow` не перекладається й не транслітерується.
- Рядки UI виноситься в ресурси, не розкидай літерали по коду.
- Продуктивність перевіряй на тексті ~3000 слів — це верхня межа сценарію.

## Збірка

Я **не можу зібрати ці проєкти** — пісочниця для запуску коду Linux, .NET Framework 4.8 і Android SDK там недоступні. Цикл роботи: я пишу код → ти збираєш (Visual Studio / Android Studio) → приносиш помилки або скріншот → я правлю. Не роби вигляд, що збірка пройшла успішно.

## Коміти

Префікс зони в повідомленні: `desktop:`, `android:`, `docs:`, `shared:`.
Ключі підпису (`*.jks`, `keystore.properties`) не комітяться ніколи.

## Дані застосунку

Windows — `%AppData%\ReadFlow\` (`students.csv`, `results.csv`).
Android — внутрішнє сховище. Жодної мережі, акаунтів чи синхронізації.
