# ReadFlow — специфікація мобільної версії (Android)

**Назва застосунку:** **ReadFlow**
**Платформа:** Android, Kotlin + Jetpack Compose
**Мінімальна версія:** Android 8.0 (API 26); ціль — актуальний API
**Тип:** офлайн-додаток, без акаунтів і мережі
**Цільовий користувач:** вчитель, який перевіряє швидкість читання учнів (часто просто з телефона в руці)
**Головні принципи:** ще жорсткіший мінімалізм, ніж на десктопі — один екран, великі кнопки, робота однією рукою

> Це «полегшена» версія настільного додатку (див. `SPEC.md`). Логіка підрахунку й формули ідентичні — див. розділ 4 у `SPEC.md`.

---

## 1. Назва та ідентифікатори

**ReadFlow** — та сама назва, що й у настільної версії: це один продукт на двох платформах.

| Де | Значення |
|----|----------|
| Назва застосунку на пристрої | `ReadFlow` |
| Application ID | `net.readflow.app` (уточніть перед публікацією в Play) |
| Кореневий пакет | `net.readflow` |
| Репозиторій | `readflow` (спільний із десктопом) |

Інтерфейс україномовний, але назва не перекладається й не транслітерується.

## 2. Що входить (і чого свідомо немає)

### 2.1 Входить

**Один головний екран** з трьома зонами згори вниз:
1. Текст (займає більшу частину екрана).
2. Компактний рядок статистики.
3. Нижня панель керування таймером (у зоні великого пальця).

**Введення тексту**
- Вставка з буфера обміну (велика кнопка «Вставити»).
- Ручний ввід/редагування.
- **Вбудовані тексти-зразки** — список готових текстів за класами/рівнями (1–4 клас, легкий/середній/складний). Це головний спосіб роботи на телефоні: вчитель обирає текст зі списку й одразу починає.
- Кнопка «Очистити».

**Статистика (компактний рядок під текстом)**
- Слова · Знаки · Букви · Середня довжина слова.
- Розгортається тапом у повний список (додатково: знаки без пробілів, речення, абзаци).
- Оновлюється автоматично з дебаунсом.

**Номер слова — довгий тап замість тултіпа**
- На телефоні немає наведення миші, тому: **довгий тап по слову** показує спливаючу підказку `Слово №N`.
- Короткий тап зарезервований під режими вимірювання (див. нижче).

**Режими вимірювання швидкості (усі три, як на десктопі)**
- **A «Тап = стоп»** — після хвилини вчитель тапає слово, де учень зупинився; додаток рахує слова до нього й показує WPM.
- **B «Таймер + стоп»** — Старт / Стоп, WPM за фактичним часом.
- **C «Помилки»** — тап по слову позначає його червоним як помилку; рахується % помилок і «чиста» швидкість.
- Перемикач режимів — сегментований контрол угорі (три великі кнопки).

**Таймер**
- Велика кнопка Старт/Стоп внизу, великий цифровий лічильник.
- Тривалість: 30 / 60 / 120 с (чіпи вибору).
- Після завершення — звук **і вібрація** (важливо: в класі шумно).
- Екран **не гасне** під час заміру (keep screen on).

**Налаштування (нижній аркуш, а не бічна панель)**
- Розмір шрифту (повзунок).
- Міжрядковий інтервал.
- Тривалість таймера.
- Тема: світла / темна / системна.
- Клас учня (для порівняння з нормами).

**Результат заміру**
- Після Стоп зʼявляється **нижній аркуш із підсумком**: WPM, знаків/хв, час, помилки, % помилок, оцінка відносно норми класу (нижче / норма / вище).
- Кнопки: «Зберегти в історію», «Поділитися» (звичайний Android Share — надіслати текст результату в Viber/Telegram/пошту), «Ще раз».

**Історія**
- Локальне збереження (Room або DataStore): імʼя/ID учня, дата, WPM, помилки.
- Простий список; свайп для видалення.
- Експорт усієї історії у `.csv` через системний «Поділитися».

### 2.2 Свідомо НЕ входить (порівняно з десктопом)

- Друк тексту.
- Гарячі клавіші.
- Підсвічування рядка «лінійкою» (на маленькому екрані рядки короткі — не потрібно).
- Тема «високий контраст» (достатньо світлої/темної).
- Відкриття файлів `.txt`, OCR, розпізнавання голосу, хмара, акаунти.
- Планшетний/ландшафтний спеціальний макет — достатньо, щоб не ламався.

## 3. Вимоги до UX (мобільна специфіка)

- **Усе на одному екрані**, без навігації між екранами. Додаткове — у нижніх аркушах (bottom sheets).
- Зона керування — **внизу**, у досяжності великого пальця.
- Мінімальний розмір цілі тапа — 48 dp. Слова в тексті мають достатній інтервал, щоб не промахуватись.
- Стан за замовчуванням: порожній текст, підказка «Вставте текст або оберіть зразок» + дві великі кнопки.
- Мова інтерфейсу — українська; підтримка темної теми й системного розміру шрифту.
- Поворот екрана / згортання додатку **не втрачає** введений текст, режим і результат заміру.
- Працює повністю офлайн; жодних дозволів (permissions) не потрібно, окрім вібрації.

## 4. Правила підрахунку

**Ідентичні десктопній версії** — див. розділ 4 у `SPEC.md`: правила слова (апостроф і дефіс не розривають), букви як Unicode-літери, середня довжина, WPM = слова / секунди × 60.

Виносяться в окремий клас `TextStatsCalculator` у чистому Kotlin, **без залежностей від Android** — щоб покривався звичайними JVM unit-тестами й за потреби переїхав у Kotlin Multiplatform.

## 5. Технічні деталі

- **Мова/UI:** Kotlin, Jetpack Compose, Material 3.
- **Архітектура:** MVVM — `ViewModel` + `StateFlow`, стан екрана як єдиний immutable `UiState`.
- **Збереження стану:** `SavedStateHandle` (переживає поворот і вбивство процесу).
- **Налаштування:** DataStore Preferences.
- **Історія:** Room (проста таблиця `attempts`).
- **Рендер слів:** `AnnotatedString` з `ClickableText` / `pointerInput` — кожне слово як анотований діапазон із власним стилем (нормальне / межа / помилка). Для тексту до ~3000 слів цього достатньо; текст будується один раз при зміні вмісту, не на кожен кадр.
- **Продуктивність:** перерахунок статистики у корутині з `debounce(300 ms)` на `Dispatchers.Default`.
- **Екран не гасне:** `keepScreenOn` лише під час активного заміру.
- **Вивід:** APK / AAB, без мережевих дозволів.

## 6. Критерії приймання (Definition of Done)

1. Вставка тексту з буфера й вибір вбудованого зразка працюють у два тапи.
2. Статистика (слова / знаки / букви / середня довжина) коректна й оновлюється без лагів.
3. Довгий тап по слову показує `Слово №N` з правильною нумерацією.
4. Режим A: тап по слову рахує слова до нього й показує WPM за обрану тривалість.
5. Режим B: Старт/Стоп дає коректний WPM за фактичним часом; після таймера — звук і вібрація.
6. Режим C: тап позначає/знімає помилку; % помилок і «чиста» швидкість коректні.
7. Підсумковий аркуш показує результат і порівняння з нормою обраного класу.
8. Історія зберігається між запусками; експорт у `.csv` через «Поділитися» працює.
9. Поворот екрана й згортання не втрачають текст і результат.
10. Немає лагів на тексті ~3000 слів на бюджетному пристрої.
11. `TextStatsCalculator` покритий JVM unit-тестами (порожній текст, апострофи, дефіси, цифри, багато пробілів).
