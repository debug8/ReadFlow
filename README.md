# ReadFlow — вимірювання швидкості читання

Простий інструмент для вчителів початкових класів: підрахунок слів у тексті й перевірка швидкості читання учнів.

Два додатки, одна логіка:

| | Платформа | Стек | Стан |
|---|---|---|---|
| [`desktop/`](desktop/) | Windows 7 → 11 | C#, WPF, .NET Framework 4.8 | не розпочато |
| [`android/`](android/) | Android 8.0+ | Kotlin, Jetpack Compose | не розпочато |

Дані застосунку зберігаються локально: на Windows — у `%AppData%\ReadFlow\`, на Android — у внутрішньому сховищі. Жодної мережі, акаунтів чи синхронізації.

---

## Навіщо це

Вчитель дає учневі текст, запускає таймер на хвилину й фіксує, скільки слів той прочитав. Зазвичай це роблять олівцем на роздрукованому аркуші та рахують слова вручну. Додаток прибирає ручний підрахунок і зберігає результати.

Три способи заміру (працюють разом):

- **A — «клік = стоп»**: через хвилину вчитель клікає слово, де учень зупинився; додаток рахує слова до нього.
- **B — «таймер + стоп»**: учень читає весь текст, швидкість рахується за фактичним часом.
- **C — «помилки»**: клік по невірно прочитаному слову; рахується «чиста» швидкість без помилок.

## Головне правило проєкту

**Правила підрахунку живуть в одному місці — [`docs/SPEC.md`, розділ 4](docs/SPEC.md).**

Обидва додатки мають давати **однакові числа** на однаковому тексті. Це інструмент вимірювання: якщо десктоп покаже 84 слова, а телефон 86, довіри до нього не буде.

Тому:

- Формули (слово, буква, середня довжина, WPM) описані один раз у `SPEC.md` і однаково реалізовані в `TextStatsCalculator` обох проєктів.
- Норми за класами й тексти-зразки **не хардкодяться** — читаються з `shared/`.
- Змінили правило підрахунку — правите специфікацію, обидві реалізації **і** тести. Усе трьома змінами в одному коміті.

Ключові нюанси правил: апостроф і дефіс не розривають слово (`комп'ютер`, `синьо-жовтий` = 1 слово), але тире й мінус — розривають; буква — це Unicode-літера **або цифра** (`2024` = слово з 4 букв); переноси рядків нормалізуються (`\r\n` = 1 знак); середня довжина слова округлюється «від нуля» й **на точному дробі** — у `Double` число `4.05` насправді трохи менше за `4.05`, тож чесне округлення дало б `4.0`.

Повний перелік із межовими випадками — розділ 4 у `SPEC.md`. Ніде більше правила не переказуються: доки їх було в кількох місцях, копії відставали від оригіналу.

## З чого почати

1. Прочитати відповідний `SPEC.md` — там повний опис функцій і критерії приймання.
2. Взяти Задачу 1 з відповідного `TASKS.md`. Кожна задача — готовий промпт для ШІ-асистента з критерієм «Готово, коли».
3. Виконувати **по одній задачі за раз**, після кожної збирати й перевіряти за критерієм. Так помилки не накопичуються.

Задачі 1–4 в обох проєктах дають працездатний лічильник слів — уже корисно саме по собі. Вимірювання швидкості додається далі.

## Умовності репозиторію

- **`.gitignore` — по папках.** Кореневий містить лише загальне; правила Visual Studio (`bin/`, `obj/`, `.vs/`) лежать у `desktop/.gitignore`, правила Gradle (`build/`, `.gradle/`, `local.properties`) — в `android/.gitignore`. Це навмисно: спільний `build/` у корені ненароком приховав би потрібні файли.
- **Гілки й коміти:** префікс у повідомленні вказує зону — `desktop:`, `android:`, `docs:`, `shared:`. Так історія читається без розкопок.
- **Ключі підпису (`*.jks`, `keystore.properties`) ніколи не комітяться** — вони вже в ігнорі, не додавайте через `-f`.
- **Теги релізів** розділяйте платформою: `desktop-v1.0.0`, `android-v1.0.0`.

## Джерела норм читання

Значення в `shared/norms.json` — орієнтовні, за наказом МОН України №1222 від 21.08.2013. У НУШ вони мають рекомендаційний, а не оцінювальний характер: додаток показує їх як орієнтир, а не як оцінку учня. Перед використанням у школі варто звіритися з чинною освітньою програмою.
